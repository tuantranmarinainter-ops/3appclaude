## TASK-1 (AI-1): `normalizeBatch` — chuẩn hoá cả thư mục

### Bối cảnh
App 1 chuẩn hoá animation từ rig nguồn bất kỳ sang GLB Mixamo65 (hợp đồng v1.0.0) bằng CLI
`packages/retarget/cli/normalize.ts` (một file nguồn mỗi lần). Kho animation dùng chung (App 5) chỉ nhận file đã qua
App 1, nên cần chạy cả thư mục một lần, chạy lại thì bỏ qua file đã làm, và có báo cáo tổng.

### Việc cần làm
Tạo `packages/retarget/cli/normalizeBatch.ts`, chạy từ `three-workspace-app/editor/packages/builder`:
```
node --import tsx ../retarget/cli/normalizeBatch.ts --src-dir <dir> --target <mixamo65.glb> --out <dir>
     [--recursive] [--skip-existing] [--armature <minecraft20-armature.bobj>] [-- <tham số chuyển nguyên cho normalize.ts>]
```
- Tìm file `.glb .gltf .fbx .bobj` trong `--src-dir` (có `--recursive` thì cả thư mục con), sắp xếp theo đường dẫn.
- Mỗi file gọi **chính `normalize.ts` bằng tiến trình con** (`process.execPath`, `--import tsx`, cùng `cwd`), ghi vào
  `<out>/<stem>/`. Mọi tham số sau `--` chuyển nguyên cho `normalize.ts` (ví dụ `--bobj --preview --action 0`).
  `--armature` chuyển cho file `.bobj`. Không chép lại logic chuẩn hoá.
- Trùng `stem` (hai thư mục con cùng tên file): thêm hậu tố `-2`, `-3`… theo thứ tự đã sắp, ghi vào summary.
- Từ chối khi `--out` nằm trong `--src-dir`, hoặc trùng nó (không ghi cạnh file nguồn).
- `--skip-existing`: bỏ qua file khi `<out>/<stem>/<stem>.manifest.json` đã có và `source.sha256` trong đó trùng
  SHA-256 của file nguồn hiện tại. File nguồn đổi thì chạy lại.
- Chạy tuần tự (một tiến trình mỗi lúc). Một file lỗi không dừng cả lượt.
- Ghi `<out>/summary.json` và `<out>/summary.tsv`. Mỗi file một dòng: đường dẫn tương đối, `stem` đầu ra, `sha256`,
  `status` (PASS / FAIL / BLOCKED / ERROR / SKIPPED), mã thoát, số Action xuất (từ manifest), mã cảnh báo chất
  lượng (`report.quality.warnings[].code`), thời gian ms, dòng lỗi cuối khi ERROR. Kèm tổng theo từng status.
- In mỗi file một dòng tiến độ ra console.
- Mã thoát: `0` nếu không có FAIL/ERROR/BLOCKED; `2` nếu có BLOCKED nhưng không có FAIL/ERROR; `1` nếu có FAIL hoặc
  ERROR. (`normalize.ts`: 0 PASS, 1 FAIL/lỗi, 2 BLOCKED.)

### Test (`test/cliNormalizeBatch.test.ts`, node:test, theo mẫu `test/cliToMinecraft20.test.ts`)
Dữ liệu trong repo: nguồn `apps/studio/public/retarget/v9.12/minecraft-actions.bobj` + armature
`minecraft20-armature.bobj` cùng thư mục; đích `builtin-assets/characters/a3d_char_30ec53c93eae4173946b38639691ebe0.glb`.
Thư mục tạm (`mkdtempSync`):
1. Chép file `.bobj` thành `a/walk.bobj` và `b/walk.bobj`, tạo `broken.glb` (byte rác). Chạy với `--recursive -- --action 0`:
   hai `walk` PASS với stem `walk` và `walk-2`, `broken` là ERROR hoặc FAIL, mã thoát `1`, summary.json/tsv đủ dòng.
2. Chạy lại với `--skip-existing`: hai file `walk` là SKIPPED, không tạo lại GLB (mtime không đổi).
3. `--out` nằm trong `--src-dir` → thoát khác 0 trước khi chạy file nào.
Giữ thời gian test hợp lý: luôn truyền `-- --action 0`.

Lệnh chạy test (từ `three-workspace-app/editor`, thay đường dẫn tuyệt đối):
`pnpm --filter @topview/3d-builder exec tsx --test <abs>/packages/retarget/test/cliNormalizeBatch.test.ts`
Typecheck: `pnpm --filter @bbs/retarget typecheck:cli`.

### Việc cần làm

   - **Gói shot** (App 2 → App 3), một thư mục: `shot.json` + các file nó tham chiếu (đường dẫn tương đối, nằm trong
     thư mục gói). `shot.json` gồm: `version`, `shotId`, `sceneId`, `fps` (=30), `frameRange` `[start, end]` (bao gồm
     cả hai đầu), `camera` (khoá theo frame: vị trí, hướng nhìn, FOV dọc độ), `characters[]` (mỗi nhân vật:

     `speed`, `loop`, `reverse`}, `placement` tại `frameRange[0]` {`position` mét, `yawDegrees`}, `rootPolicy`
     `skeletal` | `in-place`, `editable` true/false), `references[]` (GLB chỉ để xem: `file`, `sha256`, `transform`).
   - **Gói kết quả** (App 3 → App 2): `result.json` + file mới: `shotId`, `baseShotSha256` (SHA-256 của `shot.json`
     đã nhận), `edits[]` (mỗi nhân vật đã sửa: `characterId`, `originalActionUuid`, `newActionUuid`, `glb`, `manifest`,
     `glbSha256`, `placementKeys[]` {`frame`, `position`, `yawDegrees`}).
   - **Chống cộng root hai lần** (đang mở trong DECISIONS): đề xuất mặc định "vị trí sửa ở App 3 ghi vào
     `placementKeys`, root của Action giữ như cũ", và ghi rõ đây là đề xuất chờ người dùng chốt.
2. `three-workspace-app/agent/shot_package.py` (chỉ thư viện chuẩn Python 3.11):
   - `validate_shot(dir) -> list[Issue]` và `validate_result(dir, shot_dir) -> list[Issue]`;
     `Issue = {code, path, message}`, rỗng = hợp lệ.
   - CLI: `python -m agent.shot_package validate-shot <dir>` và `validate-result <result_dir> --shot <shot_dir>`;
     in JSON danh sách lỗi; mã thoát 0 hợp lệ, 1 có lỗi, 2 sai tham số.
   - Kiểm: thiếu trường / sai kiểu; `version` không phải `1.x.y`; `fps != 30`; `frameRange` ngược hoặc âm; đường
     dẫn tuyệt đối hoặc thoát khỏi thư mục gói (`..`); file không tồn tại; SHA-256 sai; `actionUuid` không có trong
     manifest của nhân vật; không có nhân vật nào `editable`; `characterId` trùng.
   - Kết quả: `baseShotSha256` khớp `shot.json`; nhân vật tồn tại và `editable` trong shot; `originalActionUuid` khớp
     `actionUuid` của shot; `newActionUuid` khác UUID gốc và có trong manifest mới; `placementKeys` nằm trong
     `frameRange`, tăng dần.
3. `three-workspace-app/agent/test_shot_package.py` (unittest): tự tạo gói mẫu trong thư mục tạm (GLB giả là vài byte,
   SHA-256 tính lúc test), một ca hợp lệ cho mỗi loại gói, và mỗi mã lỗi ở trên ít nhất một ca.

Lệnh chạy (từ `three-workspace-app`): `python -m unittest agent.test_shot_package agent.test_unified_cli agent.test_unified_mcp`
