# App 2 → AAA film assets (V4)

When `effectsPolicy` includes cues, set `W01_AAA_ASSETS` on the Studio host to a **read-only source directory** containing the saved Effekseer documents and their resource tree. Each cue's effect ID must match exactly one `<effect ID>.efkefc` basename anywhere below this directory. A missing or ambiguous document blocks export with a Vietnamese error. An omitted-effects export needs no source directory. This setting is independent of `W01_VFX_PREVIEWS` (baked sprite sheets) and replaces the old `W01_AAA_EFFECT_ROOT` replay-path setting for film export.

Keep referenced texture/model/material/curve files in their original relative locations. References such as `../textures/shared.png` work when they remain inside the source directory. Absolute references, symlinks, unsafe Windows names, missing files, and case-insensitive output collisions block export. The host reads sources only; it never saves or modifies them. Source discovery is bounded to 10,000 entries/32 directory levels; output is bounded to 2,048 files/128 MiB, each file at most 64 MiB.

The package contains `assets/effeks/project-<first 24 hex characters of SHA-256(project ID)>/<document and referenced resource tree>`. Documents keep their actual `.efkefc` bytes; `.efk` runtime exports are rejected and never renamed. The document output path becomes lowercase for Minecraft identifiers; source document paths may use ASCII letters, digits, `/._-`. Dependencies are copied relative to that mapped document parent, retaining the spelling in each resource reference. Unreferenced source files are omitted; cues and documents sharing the same dependency path copy it once. Identical files at different paths retain both paths because the documents reference those paths.

`aaa-assets.json` records the namespace, cue-to-replay path map, and SHA-256 of each packaged file. Replays use exactly `effeks/<namespace>/<document>.efkefc`. The addon `ParticleEffectIds.fromLink` removes `effeks/` and `.efkefc`; `BBSEffectLoader` adds them back before loading from `config/bbs/assets/`. The existing film-series merger carries `assets/**` across segments and deduplicates shared paths; each segment export uses the same project namespace.

The parser reads the official EFKE container `INFO` dependency table, including texture/model/material/curve types. Legacy version 1500 has six resource arrays; versions 1600–1610 have seven, and 1700–1810 use typed entries. New/unknown versions and sound dependencies block export: the addon loader does not load effect sounds. This is dependency packaging, not an Effekseer renderer or visual-equivalence check.

`bbsInstall` already installs all `assets/**` under `config/bbs/assets/` and logs only files created by that install. Identical existing files are skipped; different existing files are conflicts and are never overwritten. Uninstall deletes only owned files whose content remains unchanged; user edits and unrelated `samples` files survive. Existing transaction/rollback behavior applies equally to these assets. V3 adds destination capability checks at plan and apply; V4 does not change those checks or UI eligibility.

Reference implementation: [Effekseer 1806 EfkEfc.cs](https://github.com/effekseer/Effekseer/blob/1806/Dev/Editor/EffekseerCore/IO/EfkEfc.cs), [exporter version enum](https://github.com/effekseer/Effekseer/blob/1806/Dev/Editor/EffekseerCore/Binary/Exporter.cs), [dependency type enum](https://github.com/effekseer/Effekseer/blob/1806/Dev/Editor/EffekseerCore/Define.cs).

Validation uses generated temporary fixtures, plus read-only official sample parser checks. No game stores or user files are written. Game playback: **NOT_RUN**; packaged dependencies do not establish runtime compatibility or visual correctness.
